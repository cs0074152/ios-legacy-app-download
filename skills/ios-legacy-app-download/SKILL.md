# iOS 历史版本下载

为用户找到目标应用的可用历史版本，核对版本号与版本 ID，并在用户授权的范围内下载到本地。下载能力由上游 [ipatool](https://github.com/majd/ipatool) 提供。

## 先确认目标与环境

- 从用户请求或已有上下文获取应用名称 / App ID / Bundle ID、商店地区、目标版本或大致时间、输出位置。只补问确实影响选择的信息。
- 检查可执行文件与 `ipatool --version`、相关子命令的 `--help`。不要假设本机已安装，也不要把某个历史版本当成永久推荐版本。
- 在用户自己的交互式终端完成登录。不要要求用户把密码、2FA 码、keychain 密码短语或会话文件发送到聊天，也不要读取其明文内容作为上下文。

## 优先使用原生命令

按需阅读 [操作指南](references/workflow.md)，完成应用查询、`list-versions`、`get-version-metadata` 和 `download`。

- 区分 App ID、Bundle ID、`externalVersionID` 与显示版本号。下载前核对版本元数据，不要把版本号当作版本 ID。
- 用户只记得日期时，参考 App Store 页面展示的历史记录；日期和可下载性分别核对。网页记录可能不完整。
- 不预设版本 ID 排序代表发布时间，也不要假设版本号单调增长而进行未经验证的二分搜索。按用户目标限定候选范围，串行、适度间隔查询。
- 仅在当前工具不支持必要查询且用户确实需要排查时阅读 [旧接口参考](references/legacy-api.md)。它来自原始文档，不是持续可用的接口承诺。

## 凭据、许可与失败处理

- 会话目录随工具版本和系统变化；不要固定宣称所有凭据都在 `~/.ipatool/`，也不要声称工具不会向 Apple 发送账号信息。
- 只验证会话是否可用，避免将账号详情、Cookie、DSID 或认证日志回显。需要用户重新认证时，让用户在本机操作。
- 若需要执行 `purchase` 或带 `--purchase` 的下载，先检查当前授权是否覆盖获取该应用许可；不包含时向用户说明具体动作并确认。
- 认证、许可或地区失败时先判断原因；不要循环重试登录、验证码或购买。已知瞬时网络故障可做少量、延迟的重试；持续失败则保留错误摘要并说明下一步。

## 下载后的交付

确认输出文件存在并能作为 ZIP 读取，核对 `Payload/*.app/Info.plist` 的 `CFBundleIdentifier`、`CFBundleShortVersionString`、`CFBundleVersion` 和 `MinimumOSVersion`；元数据存在差异时如实说明。

交付文件位置、目标版本、核对结果及尚未验证的事项。下载包通常带 FairPlay 加密；不要承诺普通重签工具一定能安装，不要在未确认安装方法和备份前让用户删除现有应用。安装、修改设备和发布 IPA 需要对应的用户授权。
